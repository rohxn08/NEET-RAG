1 · Architecture

The system is a two-phase pipeline: an offline ingestion phase that builds a vector index, and an online query phase that retrieves relevant passages and generates a grounded answer.

Ingestion. PDFs are parsed page-by-page with PyMuPDF; CSV rows are serialised as natural-language strings (College: AIIMS Delhi | Category: General | Closing Rank: 52). Text is split into 500-character chunks with 80-character overlap and embedded with nomic-embed-text (768-dim). Vectors and payloads are stored in a Qdrant collection running in a Docker container.

Query. The user's question is embedded with the same model, the top-5 nearest chunks are retrieved by cosine similarity, and a similarity gate (score < 0.35 → refuse immediately) prevents hallucination when the question is entirely off-topic. Retrieved chunks are injected into the prompt as numbered context blocks. The pydantic-ai agent then produces a typed RAGResponse (answer, sources list, refused flag) so the refusal logic is enforced by the schema, not by prompt parsing.

2 · Model Choice & GPU Estimate

Development hardware. Built and tested on a CPU-only machine (no dedicated GPU). llama3.2:3b at Q4 runs at ≈ 7–10 tokens/sec on a modern CPU; embedding a 60-row CSV takes under 30 seconds.

Target deployment — NVIDIA RTX 6000 Ada (48 GB VRAM). On this card the stack is upgraded to llama3.1:70b-instruct-q4_K_M without any other code changes:

The only change needed to move from the dev LLM to the RTX 6000 target is editing one line in src/rag.py: LLM_MODEL = "ollama:llama3.1:70b". No data, index, or agent code changes.

3 · Evaluation

The evaluation set (eval/eval_set.json) contains 20 questions with pre-labelled expected behaviour. python evaluate.py runs all 20, prints a pass/fail table, and reports an overall score.

Refusal categories covered:

Pass criteria. An answerable question passes when the system returns a non-refused answer. A refusal question passes when refused = true. No partial credit; the script reports exact numbers only. Known limits: semantic similarity alone cannot catch all injection variants; the design note acknowledges this honestly.

4 · Data Privacy

Nothing leaves the machine. All inference (LLM + embeddings) is served by a local Ollama process. Qdrant writes only to ./qdrant_storage/ on disk. No network requests are made to any external service during normal operation.

Data used. The shipped dataset (data/neet_cutoffs_2024.csv) is synthetic — structurally modelled on NTA MCC published cut-offs but containing no real student records. Its licence is unrestricted.

Office deployment. In a multi-business installation each business would own a separate Qdrant collection. Access is controlled at the collection level; the pydantic-ai agent is initialised with the collection name for the authenticated user's business so NEET.info data cannot be queried by a Hirrx session.

Logs. Streamlit writes no access logs by default. If logging is added, query text must not be written to a shared log file accessible to other business units.
